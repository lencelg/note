# file
文件名 `prog.c` 。圆点后面的部分称为 文件扩展名(fiJe extension), 在linux中文件扩展名包含了额外的格式信息和和读取方式

下面介绍二进制文件

一个简单的可执行文件: 文件头以魔数 (magic number) 开始(表明该文件是一个可执行的文件, 防止非这种格式的文件偶然运行),魔数后面是文件中各段的长度、执行的起始地址和 一些标志位,程序本身的正文和数据在文件头后面。这些被装入内存，并使用重定位位重新定位, 符号表则用干调试 。

UNIX的存档文件: 它由己编译但没有链接的库过程（校块）组合而成。每个文件以模块头开始，其中记录了名称、创建日期、所有者、保护码和文件大小。该模块头与可执行文件一样，也都是二进制数字，打印输出它们毫无意义。

# file system implementation
系统结构布局如下

![](./img/file%20system%20architecture)

| 组成部分 | 功能说明 |
|----------|----------|
| **主引导记录（MBR）** | 位于磁盘的0号扇区，用于引导计算机。BIOS读入并执行MBR，其中包含分区表和引导代码。 |
| **分区表** | 位于MBR的结尾，给出每个分区的起始和结束地址，并标记其中一个分区为活动分区。 |
| **引导块** | 每个分区从引导块开始。MBR确定活动分区后，读入其引导块并执行，引导块中的程序装载该分区中的操作系统。 |
| **超级块** | 包含文件系统的所有关键参数，如魔数（确定文件系统类型）、文件系统中块的数量等。在计算机启动或文件系统首次使用时读入内存。 |
| **空闲空间管理** | 记录磁盘分区中空闲块的信息（例如位图或指针列表），用于管理空闲块的分配与回收。 |
| **节点（i节点）** | 一个数据结构数组，每个文件对应一个节点，用于说明文件的属性及数据块位置等信息。 |
| **根目录** | 存放文件系统目录树的根部，是访问整个文件系统的起点。 |
| **文件和目录** | 磁盘分区中剩余的空间，用于存放其他所有的目录和文件内容。 |

## file implementation
problem: 如何记录各个文件分别用到哪些磁盘块

solution1: **线性连续分配** , 简单但是删除文件会造成碎片问题，整理碎片的代价很大

solution2: **链表分配** , 每个文件分成几块，块中包含一个块的位置信息, 但是指针的读取和内存造成了一定开销

solution3: 采用内存中的表进行链表分配, 在内存中放置一个 **文件分配表** (File ALiocation Table, FAT),其中包含了所有文件的起始块的位置信息， 但是要把所有文件的信息都放在表中.

solution4: 使用包含了文件属性和文件块的磁盘地址的 **i节点 (index-node)** 的数据结构, **机制** 是只有在对应文件打开时，其 i 节点才在内存中 。

## virtual file system
虚拟文件系统 (Virtual File System , VFS) 概念尝试将多种文件系统统一成一个有序的结构。不同分区的文件系统可能是不同的

basic idea: 抽象出所有文件系统都共有的部分 ， 并且将这部分代码放在单独的一层，该层调用底层的实际文件系统来具体管理数据。
