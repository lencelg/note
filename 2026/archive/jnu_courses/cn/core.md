# 计算机网络核心考点笔记

# 一、网络性能指标
**速率 (Rate)** ：单位包括 bit/s, kb/s, Mb/s, Gb/s。
**带宽 (Bandwidth)** ：表示网络最高传输能力，单位是 bit/s。
**吞吐量 (Throughput)** ：指实际传输速率。例如：100Mbps的链路，实际只跑到了80Mbps，则吞吐量即为 80Mbps。
**时延** ：由四部分组成，即发送时延、传播时延、处理时延和排队时延。

# 二、物理层 (Physical Layer)
**1. 曼彻斯特编码**
重点在于每个码元中间必有一次跳变。其作用是用来表示数据，并提供同步时钟。

**2. 传输介质**
*   **双绞线** ：主要作用是降低电磁干扰（注意：是降低电磁干扰，不是降低电阻！）。
*   **同轴电缆** ：抗干扰好，但目前已不是主流局域网介质。
*   **光纤** （重点对比）：
    *   **单模光纤** ：芯径小，使用激光器，适合长距离传输。
    *   **多模光纤** ：芯径大，使用LED。

**3. 码片设计**
核心原理是码片向量正交内积为0。示例：`(+1,+1,-1,+1)` 与 `(+1,-1,+1,+1)` 相乘求和的结果是 0。

**4. 时延计算**
需要掌握两个核心公式：
*   **发送时延** = 数据长度 ÷ 带宽
*   **传播时延** = 距离 ÷ 传播速度

**5. 香农公式**
*   **码间串扰** ：接收端收到的信号波形失去了码元之间的清晰界限。
*   **奈氏准则**：码元传输的最高速率 = 2W（码元/秒）。
*   **信噪比**：信号的平均功率 $S$ 和噪声的平均功率 $N$ 之比，记为 $S/N$，用分贝（dB）度量。
    *   计算公式：**信噪比(dB) = $10 \log_{10}(S/N)$**
    *   示例：当 $S/N = 10$时，信噪比就是 10dB；当 $S/N = 1000$ 时，信噪比为 30dB。
*   **信道的极限信息传输速率 C**：
    *   公式：$C = W \log_2(1 + S/N) (bit/s)$ （其中 $W$ 为带宽Hz，$S$ 为信号平均功率，$N$ 为高斯噪声功率）。

**6. 复用技术**
*   **FDM (频分复用)** ：应用于广播电视。
*   **TDM (时分复用)** ：应用于PCM电话。
*   **WDM (波分复用)** ：应用于光纤通信。
*   **CDM (码分复用)**

# 三、数据链路层 (Data Link Layer)

1. CSMA/CD (高频考点)
*   **记忆口诀**：先听后发，边听边发，冲突停发，随机重发。
*   **流程解析**：先监听信道，如果空闲则立即发送并**边发送边监听**；若信道不空闲则继续监听。发送过程中一旦检测到冲突，**立即停发**。这是第 \(k\) 次冲突时：
    1.  若 \(k \le 15\)：执行“随机等待一段时间”算法，重试发送。
    2.  若 \(k = 16\)：直接传输失败，放弃该帧，并报告网络层。
*   **退避算法**：
    *   **争用期** = 2 × 最远单向传播时延。如果在争用期内未检测到冲突，说明本次帧发送不会再发生冲突。
    *   **截断二进制指数退避算法**：随机等待时间 = 随机数 \(r\) × 争用期。取 \(r\) 的规则是：若 \(k \le 10\)，在 \([0, 2^k - 1]\) 区间取随机整数；若 \(k > 10\)，在 \([0, 2^{10} - 1]\) 区间取随机整数。

2. 透明传输与PPP协议
*   **透明传输**：采用**字节填充**。三个特殊字符为 `SOH`、`EOT`、`ESC`。处理方法：当出现 `ESC` 时，再插入一个 `ESC`。
*   **PPP协议状态机**：
    1.  链路静止 ↔ 物理链路建立 → 链路建立。
    2.  链路建立 ↔ LCP配置协商（若失败则进入链路终止） → 鉴别。
    3.  鉴别 → 鉴别失败（进入链路终止）/ 鉴别成功或无需鉴别 → 网络层协议。
    4.  网络层协议 ↔ NCP配置协商 → 链路打开（此时为已鉴别的LCP链路和NCP链路）。
    5.  链路打开 ↔ 链路故障/关闭请求 → 链路终止（最终回到链路静止状态）。

3.交换机自学习
*   **学习源MAC**：收到帧后取出**源MAC**。若交换表中无此地址，则记录（地址、接口、有效时间）；若有，则更新该地址项（刷新接口与有效时间）。
*   **转发目的MAC**：取出**目的MAC**。若表内无此地址，向**除进入接口外的所有接口**泛洪转发。若有此地址，检查其**对应接口**是否与**帧进入的接口**一致：一致则**丢弃**；不一致则向**指定接口**转发。

4. CRC计算与停止等待协议
*   **CRC计算（必考）**：必须掌握模2除法、生成多项式的运算及CRC余数的计算。
*   **停止等待协议（效率低）**：流程为发送 → 等待ACK → 超时重传。信道利用率公式：$U = \frac{T_d}{T_d + RTT}$（其中 $T_d$ 为发送数据帧耗时，$RTT$ 为往返时延）。

# 四、网络层 (Network Layer)

**1. IP分片**
*   **首部结构**：包含版本、首部长度、区分服务、总长度、标识、标志、片偏移、生存时间(TTL)、协议、首部校验和、源/目的地址等。
*   **关键字段**：
    *   **标识 (16位)** ：用于生成IP数据报的唯一标识。
    *   **片偏移 (13位)**：指出分片在原始报文中的位置，**偏移单位固定为 8 字节**。
    *   **标志 (3位)** ：
        *   **MF (最低位)** ：MF=1表示后面还有分片，MF=0表示是最后一片。
        *   **DF (中间位)** ：只有DF=0时才允许分片。

**2. IP交付与ICMP协议**
*   **IP交付**：同一网络内为**直接交付**，经过路由器为**间接交付**。
*   **ICMP协议** ：IP层协议，封装于IP数据报中。
    *   **差错报告报文**：终点不可达（IP或端口不存在）、时间超过（TTL过期或分片重组超时）、参数问题（首部非法）、改变路由（重定向）、源点抑制（已废弃）。
    *   **询问报文**：回送请求/回答（Ping的基础）、时间戳请求/回答。
*   **不必反馈ICMP差错的情况**：
    1.  携带ICMP差错的IP数据报本身出错。
    2.  被分片的IP数据报，无论几片出错，统一只反馈1次。
    3.  多播目的地址。
    4.  源地址为特殊地址（如 127.x.x.x, 0.0.0.0）。
*   **典型应用**：`ping`（基于回送请求/回答）；`traceroute`（基于时间超过报文）。

**3. 路由协议 (CIDR, RIP, BGP)**
*   **CIDR**：要求掌握子网掩码、网络地址、主机号的计算。
*   **RIP协议 (距离向量算法)**：
    *   收到邻居 $X$ 的报文：将下一跳改为 $X$，所有距离+1。随后逐一比对：
        1.  若路由表中无目标网络 $N$，直接添加。
        2.  若下一跳就是 $X$，无条件**替换**。
        3.  若新距离**小于**表中距离，**更新**。
        4.  否则，**什么也不做**。
    *   **超时判定**：若3分钟未收到邻居更新，则标记为**不可达**（距离设为16）。
*   **BGP协议**：**eBGP** 用于自治系统AS之间，**iBGP** 用于自治系统AS内部。

**4. 路由器转发与最长前缀匹配**
*   **原则**：同时匹配多条路由时，选择**网络前缀最长**（即掩码最长、匹配最精确）的那一条。
*   **示例**：目的IP `128.1.2.132` 同时匹配 `/26` 和 `/25`，根据最长前缀匹配，最终会选择精确度更高的 **`128.1.2.128/25`**。

**5. ARP协议与OSPF算法**
*   **ARP协议**：实现IP ↔ MAC地址的转换。流程为：**ARP Request** 广播请求 → **ARP Reply** 单播应答。
*   **OSPF协议** ：链路状态路由协议，底层使用 **Dijkstra (迪杰斯特拉) 算法** 计算最短路径树。

# 五、传输层 (Transport Layer)

**1. UDP与TCP滑动窗口**
*   **UDP**：特点是无连接、不可靠、面向报文。
*   **TCP滑动窗口** （设 \(P_1\) 为后沿，\(P_2\) 为当前，\(P_3\) 为前沿）：
    *   **\(P_3 - P_1\)** = 发送窗口（也称通知窗口）。
    *   **\(P_2 - P_1\)** = 已发送但**尚未收到确认**的字节数。
    *   **\(P_3 - P_2\)** = 允许发送但**尚未发送**的字节数（即可用窗口）。

**2. TCP超时重传与RTT计算**
*   **加权平均往返时间 (\(RTT_S\))** ：
    *   公式：新的 $RTT_S = (1 - \alpha) \times \text{旧的 } RTT_S + \alpha \times \text{新的 } RTT \text{ 样本} $ ，其中RFC 6298推荐 $\alpha = 1/8$。
*   **超时重传时间 (\(RTO\))**：需略大于 \(RTT_S\)。公式：**\(RTO = RTT_S + 4 \times RTT_D\)**（\(RTT_D\)为RTT偏差的加权平均）。
*   **RTT偏差 (\(RTT_D\))** ：
    *   公式：新的 $RTT_D = (1 - \beta) \times \text{旧的 } RTT_D + \beta \times |RTT_S - \text{新的 } RTT \text{样本}|$，RFC 6298推荐 $\beta = 1/4$

**3. TCP拥塞控制**
*   **四种算法(RFC 5681)** ：慢开始 (slow-start)、拥塞避免 (congestion avoidance)、快重传 (fast retransmit)、快恢复 (fast recovery)。
*   **流量控制 vs 拥塞控制** ：流量控制防止接收方处理不及，依赖 `rwnd`（接收窗口）；拥塞控制防止网络过载，依赖 `cwnd`（拥塞窗口）。
*   **核心公式**：实际发送窗口 = **`min(rwnd, cwnd)`**

# 六、应用层 (Application Layer)

*   **DNS**：重点掌握递归查询和迭代查询。
*   **FTP**：控制连接使用 **21端口**，数据连接使用 **20端口**。
*   **URL格式**：标准为 `协议://主机:端口/路径`。
*   **DHCP**：牢记 **DORA 四步流程**，即 `Discover` (发现) → `Offer` (提供) → `Request` (请求) → `ACK` (确认)。
*   **SMTP / HTTP**：用于邮件服务器之间的邮件传输。
*   **加密机制对比**：
    *   **对称加密**：速度极快，适合大数据加密。代表算法：**AES、DES**。
    *   **非对称加密**：速度慢，用于密钥交换、数字签名。代表算法：**RSA**。
